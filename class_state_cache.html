Detailed Description

template<class Record>
class StateCache< Record >

Small cache for computed property records

A numerical Jacobian re-evaluates every medium state of a model, although most of them get exactly the same inputs as in the evaluation before. This cache keeps the results of recent calls, so that a repeated call can copy the stored record instead of calling the property library again.

How it works, in short:

  • The cache is a fixed list of slots (a "direct-mapped" cache).
  • The inputs (input pair, x1, x2, phase) are turned into a slot number with a hash function, a recipe that scatters similar inputs over all slots.
  • A lookup checks only that one slot. If the stored inputs are bit for bit identical to the new inputs, the stored record is returned (a "hit").
  • Otherwise the caller computes the record and stores it in that slot, replacing whatever was there before (a "miss").

Inputs are compared on their exact bit patterns, so the results are the same as without the cache, as long as the property calculation itself always gives the same result for the same inputs.

Record is the property struct that is stored, for example ExternalThermodynamicState or ExternalSaturationProperties.

The cache is not thread-safe, just like the solver objects that use it.
